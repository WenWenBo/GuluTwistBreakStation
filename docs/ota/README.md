# OTA 自动更新文档

整理日期：2026-10-14。面向项目维护者与后续实施者。当前已完成需求澄清，尚未接入更新器；本轮实施以 [OTA 需求与设计](../plans/2026-10-14-github-ota-design.md) 为准，其余文档提供调研与原理参考。

## 结论

保留 Rust + GPUI，采用 Velopack 官方 Rust SDK + GitHub Releases，向所有兼容平台用户提供更新。首版覆盖 Windows x64、Mac Apple Silicon 和 Mac Intel；不引入账号、灰度、更新服务器、对象存储或 CDN。Windows 提供安装版，Mac 按架构提供应用包。

启动后及常驻期间每 12 小时自动检查并后台下载，下载完成后弹窗提供“立即重启”和“稍后”。用户选择稍后，则同一版本本次运行不再弹窗，下次启动再提醒，不能自动安装缓存包。休息与锁屏期间延后提示；“关于小站”保留手动更新入口及自动检查下载开关。

更新只在用户确认且数据保存成功后应用，不需要重启操作系统。旧版本没有更新器，需要手动迁移一次；离线和更新失败不影响本地提醒。已下载且完整性校验通过的包允许离线主动安装。

发布采用自动构建草稿、维护者验证后手动公开的流程。首版使用全量包，不接入付费平台签名、公证或额外的更新清单签名验证，保留 HTTPS、Mac 必要的临时签名和 Velopack 自带的包完整性校验。

## 术语约定

- **OTA / 自动更新**：客户端获取更新内容并在本机应用，用户不必反复手工下载安装。
- **全量包**：目标版本完整的更新内容。
- **差分包**：需要结合旧包还原目标版本的变化数据；主要节省网络流量。
- **整体替换**：切换到完整的新应用目录、bundle 或 AppImage；可与差分下载同时使用。
- **热更**：容易有歧义。本文明确区分“重启生效的代码包更新”和“保持进程运行的代码热替换”；当前建议方案是前者的自动更新体验。
- **更新源**：版本清单和产物的获取方式，可以是 GitHub、HTTP 服务或自定义接口。
- **灰度**：只向部分合格安装提供一个目标版本，不等于发布一个 beta 标签。

## 实施顺序

1. 统一版本来源，锁定兼容的 SDK 与打包工具，生成 Windows 安装版和两种 Mac 的全量更新产物。
2. 接入后台检查、下载、完成弹窗、“稍后”、手动更新及受控保存退出；关闭更新器默认的启动自动应用行为。
3. 修改发布流水线，使三个目标的构建产物汇总到草稿，由维护者验证后手动公开。
4. 使用两个递增版本分别实测三个目标的更新、完整性校验、数据保留、失败处理及旧包迁移。

Linux、差分、灰度、额外的签名验证与自动回退不属于本轮。包完整性校验不等于发布者签名认证，替换程序成功也不自动意味着新版业务健康；详细边界以已确认设计为准。
