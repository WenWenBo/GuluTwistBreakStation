# 紧凑胶囊 · 本机补验与 Windows 10 / Intel Mac 手工验证

日期：2026-10-13。适用：`feat/compact-floating-capsule`，0.1.0 / Mac build 4。

这是操作手册，不是通过报告。开发 Mac 已补验主要交互；已测子项及尚未完成的边界见报告，不能把同一编号下的部分通过当作整项通过。先补齐本机剩余项目，再到其它机器执行。原有提醒、安装与稳定性验收仍按[基础手册](MANUAL_TEST_GUIDE.md)执行；本次已取得的证据见[报告](FLOATING_WIDGET_REPORT.md)。

## 1. 准备正确版本

1. 从菜单栏／托盘退出旧版，避免操作到仍在运行的旧进程。保留日常数据，使用下面的独立测试目录。
2. Intel Mac 使用 `GuluTwist-0.1.0-build4-x86_64-apple-darwin.zip`，解压到一个独立文件夹。当前 Apple Silicon 使用文件名中 `aarch64` 的包。无需 Rust 即可运行 Mac 包。
3. 在“关于本机”确认 macOS 15+，记录系统构建、芯片、内存，以及所有屏幕的排列、分辨率和缩放。Intel 的通过结果必须来自 Intel 硬件。
4. Windows 需先原生构建。当前 Mac 没有生成本功能的 Windows EXE；不能拿旧版本包验收胶囊。准备 Windows 10 22H2 x64、支持 DirectX 的显卡与驱动。构建机可用 Windows 11，运行验收仍在 Windows 10。
5. Windows 构建机安装 Rust、Visual Studio 2022 C++ Build Tools 和 Windows SDK，打开 Developer PowerShell，在仓库执行：

```powershell
git fetch origin
git switch --track origin/feat/compact-floating-capsule
# 已有同名本地分支时，改用 git switch feat/compact-floating-capsule
cargo test --workspace --locked
cargo check --workspace --locked
./scripts/package-windows.ps1 -SkipInstaller
```

命令失败则停止并保留输出。便携 ZIP 位于 `dist`；需要安装包时先安装 Inno Setup 6，再运行不带 `-SkipInstaller` 的打包脚本。不要为测试推送 `release`，它会触发仓库的公开发布工作流。

记录 `git rev-parse HEAD`；Mac ZIP 用 `shasum -a 256 文件.zip`，Windows 用 `Get-FileHash 文件.zip -Algorithm SHA256`，与报告中的包哈希或本次构建记录对照。个人 Mac 包是 ad-hoc 签名、未公证；系统信任提示由你核对来源后操作。

## 2. 隔离测试数据

Mac 在终端执行；先把应用路径替换成实际解压位置：

```bash
mkdir -p "$HOME/GuluTwistCapsuleTest"
GULU_DATA_DIR="$HOME/GuluTwistCapsuleTest" GULU_DIAGNOSTICS=1 \
  '/实际解压目录/GuluTwist Break Station.app/Contents/MacOS/gulu-twist' \
  2> "$HOME/GuluTwistCapsuleTest/runtime.log"
```

Windows 在 PowerShell 执行，替换 EXE 路径：

```powershell
$env:GULU_DATA_DIR = Join-Path $env:USERPROFILE 'GuluTwistCapsuleTest'
$env:GULU_DIAGNOSTICS = '1'
New-Item -ItemType Directory -Force $env:GULU_DATA_DIR | Out-Null
& 'C:\实际解压目录\gulu-twist.exe' 2> (Join-Path $env:GULU_DATA_DIR 'runtime.log')
```

后续重启都用同一命令，才能继续使用测试数据。不要直接双击而误切回日常数据。测试完成从托盘退出，再关闭测试终端即可。

首次配置：选中今天，设置覆盖接下来至少一小时的工作时段；喝水间隔 5 分钟，其余保持更长；喝水休息 10 秒，先用轻提醒。开启“显示桌面悬浮窗”，确认引导。在主窗口记录起始倒计时和今日记录数量。

## 4. 锁屏与真实睡眠

1. 在正常倒计时中记下剩余值，**锁屏 60 秒**，解锁。核对间隔没有扣掉锁屏时间，胶囊重新出现且与主窗一致。诊断日志应记录 `locked=false->true` 与 `true->false`。
2. 将正式强制休息设为 2 分钟，等自然到期后通过系统菜单真正“睡眠”，等待至少 2 分钟，再唤醒和解锁。锁屏不能替代睡眠。
3. 回来后过期遮罩不应重现，胶囊恢复，今日正式记录每项仅一条。下一提醒遵循至少 60 秒恢复缓冲。
4. 日志中睡眠期间 `continuous_delta_ms` 应明显大于 `awake_delta_ms`。只有锁屏日志时，结果填“锁屏已验证，真实睡眠未证实”。
5. 另测关闭悬浮开关后做一次休息：结束不能擅自重新开启胶囊。
