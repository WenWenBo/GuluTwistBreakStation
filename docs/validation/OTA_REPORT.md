# OTA 实现与验证报告

日期：2026-10-14。实现版本 **0.1.1**，验证升级版本 **0.1.2（仅本地测试）**。实现已落地；发布前仍有原生平台与公开 GitHub 链路验收，不能视为三目标已全部上线。

## 已实现

- 固定公开 GitHub 仓库、三架构稳定渠道、正式版本、全量更新，无账号/灰度/服务器/差分/签名密钥体系。
- 启动 hook 前置，并关闭 Velopack 默认的启动自动应用；开发二进制不具备安装布局时仍能使用提醒。
- 后台检查下载，启动抖动、12 小时周期、快速重启限频、手动冷却和失败退避；网络调用有超时，单任务与操作序号防重复。
- 独立更新偏好键，损坏/未来格式保留原数据并停用 OTA；缓存原始摘要/大小/版本/身份/渠道持久化，恢复和安装前复核。
- 关于页、自动更新开关、可访问的独立弹窗、稍后/冷启动提示、休息/锁屏延后、隐藏草稿保护。
- 保存前冻结新业务操作、事务提交最终记录/暂停/UI/OTA 偏好、有结果的屏障；超时取消授权，迟到提交仅对齐状态；只在最终确认后启动辅助程序并正常关闭数据库。
- Mac 双架构 vpk 包；Windows 用户级 Setup 脚本和版本/AUMID 资源；统一 Cargo 版本。
- 三目标 CI、产物校验、仅草稿发布、相同原始产物中断恢复、拒绝覆盖公开版/异提交/异摘要；文档与迁移说明。

## 实现边界

SDK 自带 GithubSource 没有请求超时且会跳过失败 feed，因此使用窄范围的 GitHub UpdateSource 适配器。请求仍采用 SDK 的 HTTPS 下载实现，包处理/安装仍由 Velopack 完成。该 HTTP 接口不提供响应头，不能读取 Retry-After，按本地退避处理。

准备重启的十秒超时立即取消安装授权；复核线程未结束时不并发创建第二个更新任务。若 SQLite 已进入提交，短暂保持业务写入冻结直到回执，以免恢复旧内存而与已提交记录冲突；该事务采用现有 100ms busy timeout，界面线程不执行磁盘事务。无法取消操作系统中卡死的磁盘 I/O。普通退出的旧容错屏障仍存在，但不能推进 OTA。

用户没有要求正式签名或额外验签，因此只使用 HTTPS、原始摘要/大小和安装身份核对、Mac ad-hoc 签名。不承诺自动降级、更新器退出后的应用内错误提示或新版数据库回退。坏版本用更高版本修复，个人数据保留。
