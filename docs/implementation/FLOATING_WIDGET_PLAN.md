# 咕嘟扭扭｜紧凑胶囊悬浮窗实现计划

版本：1.1 · 日期：2026-10-13

状态：功能代码已实现；自动检查与 Mac 双架构构建通过。解锁后本机主要桌面交互已补验；完整边界回归、Windows 原生构建与外机实测待完成。详见[验证报告](../validation/FLOATING_WIDGET_REPORT.md)。

本计划面向后续开发与验收，基于用户确认的 **200 × 52、两端完整半圆** 胶囊方案，以及当前 Rust / GPUI Kit 工程。设计依据见 [悬浮窗方案](../design/FLOATING_WIDGET_PROPOSAL.md)，已有功能基线见 [界面规范](../design/UI_SPEC.md)。

执行顺序沿用用户要求：先在当前 Mac 完成本机功能与验证，再完善 Windows 10 和 Intel Mac 的适配与构建；本机版本稳定后交付外机手工验证文档，由用户运行确认。平台代码完成、构建成功、实机验证分别记录。

## 1. 目标、范围与默认行为

用户关闭主窗口后，仍能通过一个小巧的桌面胶囊查看最近事项和剩余有效工作时间。设置、今日记录和提醒处理继续在主窗口完成，强制休息继续使用现有多屏遮罩。

### 1.1 本轮交付

- 200 × 52 的单个胶囊窗口，应用图标、事项名称、倒计时及更多菜单。
- 普通桌面置顶、被动更新不抢焦点、拖动与位置恢复。
- 设置和托盘中的显示／隐藏入口，以及重置位置。
- 与现有引擎一致的正常、稍后、暂停、非工作时段、到期、异常状态。
- 正式休息和遮罩体验期间临时隐藏，结束后按用户开关恢复。
- 本机验证报告、Mac 双架构包、Windows 适配与构建结果、外机专项验证步骤。

### 1.2 执行默认值

以下细节沿用已接受方案，并在本计划中明确，开发时不再分别增加选择步骤：

| 项目 | 实施规则 |
| --- | --- |
| 初始开关 | 旧用户升级默认关闭；新用户首次引导可选择开启，选择前不开启 |
| 冷启动 | 已完成引导、悬浮开关开启、数据正常且托盘可用时，显示托盘和胶囊；其他情况保持主窗口入口 |
| 显式打开应用 | 点击 Dock、托盘“打开小站”、胶囊图标／时间或重复启动已有进程时，打开主窗口 |
| 隐藏 | “隐藏悬浮窗”持久化为关闭；退出重启保持关闭，不暂停提醒 |
| 临时隐藏 | 锁屏、正式休息、体验遮罩及应用退出阶段隐藏，不修改用户开关 |
| 放置 | 首次在主屏可用工作区右下角，胶囊可见轮廓距边缘约 24 逻辑像素 |
| 屏幕数量 | 始终只有一个胶囊；可拖到另一屏，不为每个屏幕复制 |
| 明暗外观 | 胶囊随系统明暗使用预览配色；局部处理，不修改主窗口现有浅色主题 |
| 全屏／Space | 目标是在普通桌面及普通 macOS Space 可见；全屏应用行为单独记录，不要求覆盖系统安全桌面或独占全屏 |

本轮不增加圆球切换、尺寸调节、贴边自动缩成图标、透明度设置、动画养成或新的提醒种类。预览中的尺寸调节仅用于设计确认，正式版固定为已确认尺寸。保留现有离线、免登录、无开机自启的范围。

## 2. 固定视觉规格

| 元素 | 规格与要求 |
| --- | --- |
| 可见胶囊 | 200 × 52 逻辑像素；圆角半径 26，两端为完整半圆，上下边平直 |
| 原生窗口外框 | 可增加必要的透明阴影边距；200 × 52 指可见胶囊，不把阴影算进内容尺寸 |
| 内容布局 | 水平留白约 8、垂直留白约 6、三列间距约 6；边框计入总尺寸 |
| 应用图标 | 38 × 38 布局盒，图案可见部分约 31 × 31；复用内嵌 `gulu/app.png` |
| 事项名称 | 字号 12、行高 15；例如“咕嘟喝水”“扭扭颈肩”“放风一下”“站一站” |
| 倒计时 | 字号 20、行高初值 23，Mac Menlo / Windows Consolas，常规字重，等宽数字 |
| 更多入口 | 右端垂直居中，28 × 28 鼠标点击区；必须始终可发现 |
| 浅色 | 底色 `#FCFCF6`、文字 `#243D35`、辅助文字 `#607068`、倒计时 `#2F6B58`、边线 `#DCE5DA` |
| 深色 | 底色 `#253B33`、文字 `#EDF4E8`、辅助文字 `#BACABD`、倒计时 `#B8DDBF`、边线 `#456052` |
| 阴影 | 轻量、柔和，不画第二层厚底板；两端外围真正透明 |

`00:00`、`00:01`、`18:32`、`120:00`、`240:00` 都须完整显示；不缩窄数字以迁就容器。GPUI 的实际字形边界与 HTML 不一定相同，先实测字体、行高和留白；保持外框尺寸及可读性，必要时微调内部间距。禁止直接复用主窗口带额外水平留白和 1.4 倍行高的数字组件后任其溢出。

名称过长时采用产品短名；多项并列显示“喝水 + 1 项”，完整名称通过工具提示或主窗口查看。非工作时段的下一开始时间可用“明天 09:00”／“周一 09:00”等短标签，不让完整日期挤压胶囊。

## 3. 状态数据与计时规则

### 3.1 唯一计时来源

胶囊读取 Controller 发布的结构化状态。提醒引擎继续决定何时到期、何时暂停、何时合并和何时结束休息。胶囊不维护自己的截止时间，不解析 `Snapshot.remaining` 的中文字符串，也不每秒独立减一。

在 `gulu-core` 增加只读的提醒摘要查询，返回事项、阶段、剩余毫秒、待处理列表等语义数据；在应用层转换为胶囊显示状态和中文文案。接口名称可随代码风格调整，不新增调度引擎或 crate。

最近事项的计算规则：

1. 仅考虑启用事项；`Waiting` 取运行态剩余毫秒，`Snoozed` 取稍后阶段自身剩余毫秒。
2. 以实际毫秒排序，显示时统一向上取整为秒；不能按显示字符串排序。
3. 已通知的待处理项优先显示；未通知但已经到期的项显示“待提醒”，不误写为“已提醒”。有多项时聚合数量，并保留每项真实通知状态。
4. 并列最早按 `ReminderKind::ALL` 固定顺序显示。仅“展示取整后相同”但实际时间不同的项目，不当成同一到期批次。
5. 打开窗口、拖动、切换明暗、开关和重置位置均不能发出 `Manual`、`Respond`、`Save(Settings)` 等改变提醒规则或记录的命令。

当前引擎的恢复缓冲会直接把剩余值提高到至少 60 秒，并没有独立的“恢复准备中”阶段。因此唤醒后直接显示核算后的真实时间；不能仅凭时间等于 60 秒就猜测正在缓冲。强制提醒约 1 秒合并等待及轻提醒冷却期间，依据 `Pending.notified` 显示“待提醒”，无需新增第二个缓冲倒计时。

### 3.2 显示优先级

先判断可见性，再判断内容。退出中、用户关闭、锁屏、正式休息、体验遮罩优先隐藏；其余状态按以下顺序选择。

| 优先级 | 场景 | 胶囊内容和动作 |
| --- | --- | --- |
| 1 | 首次引导未完成／核心数据恢复 | 先展示主窗口处理，不用无效倒计时替代引导 |
| 2 | 数据写入异常等需要用户处理的错误 | 简短“需要处理”与主窗口入口；具体错误留在主窗口；UI 偏好保存错误单独显示，不覆盖记录错误 |
| 3 | 所有提醒已关闭 | “提醒未开启”，点击进入设置 |
| 4 | 手动或定时暂停 | “已暂停”，显示简短恢复时间或提示；菜单提供恢复 |
| 5 | 非工作时段 | “下班啦”与下次开始时间，不继续减小提醒间隔 |
| 6 | 存在已到期事项 | “喝水时间到／待处理”或“待提醒”；点击进入首页现有处理区 |
| 7 | 普通等待／稍后 | 最近事项与 `MM:SS`，稍后状态用短标签说明 |

同一次快照更新主窗口和胶囊；两处都显示时间时应一致。强制会话自然结束、紧急退出、体验结束、工作时段结束或遮罩创建失败后，重新依据真实状态决定是否恢复胶囊，不能只依赖单个“休息结束”回调。

## 4. 窗口与交互实现

### 4.1 原生窗口

- 使用专门的悬浮窗配置函数，创建时不激活应用；被动显示、恢复、刷新和移动校正不调用全局激活接口。
- 窗口不带标题栏、最小化或缩放按钮；用户拖动位置，不能拉伸尺寸。
- 置于普通应用窗口上方，低于正式休息遮罩。Mac 不能仅依赖名为 `Floating` 的窗口类型，须验证跨应用失焦后的行为。
- Windows 处理工具窗口、置顶和非激活显示，不新增独立任务栏／Alt-Tab 项；避免无条件禁用激活后导致菜单键盘操作失效。
- 验证真实透明边缘和鼠标命中。阴影留白不应变成明显的透明拦截区；菜单关闭、胶囊隐藏和退出后不能残留拦截窗口。

### 4.2 菜单与焦点

200 × 52 不足以容纳展开菜单。先验证 GPUI Kit 菜单在小原生窗口上的裁剪情况；若组件在父窗口内绘制，改用平台支持的独立弹出菜单窗口或原生菜单。菜单显示在胶囊附近，靠近屏幕边缘时自动翻转，不通过放大胶囊来容纳菜单。

菜单提供“打开小站”“提醒设置”“暂停提醒／恢复提醒”和“隐藏悬浮窗”。暂停选项复用现有 15 分钟、1 小时、下一工作日和手动暂停语义。

被动倒计时不抢焦点；用户主动打开菜单可以获得必要的交互焦点，支持键盘导航、Esc 收起和外部点击关闭。主动点击图标或时间才打开并激活主窗口。“提醒设置”通过明确的导航命令进入设置，保留已有未保存表单保护，不能借用 `saved()` 清理草稿。

关闭操作按窗口来源路由：主窗口保持现有关闭行为；胶囊的系统关闭请求隐藏胶囊并保存开关；菜单内 Esc 只关闭菜单；正式遮罩的 Esc／关闭仍结束本次休息。现有全局 `CloseWindow` 会把非休息场景转为 `Hide`，实施时需要补充窗口身份，避免胶囊接收关闭操作时错误隐藏主窗口。

### 4.3 拖动与位置

- 胶囊背景用于拖动；图标和倒计时支持点击打开，也须区分拖动手势。建议移动超过 4 个逻辑像素后判为拖动，完成拖动不触发点击。更多按钮不启动拖动。
- 优先使用 GPUI／系统原生拖动，不做每帧写入文件的自定义拖拽循环。松手保存位置；若平台只提供连续移动回调，使用约 300 毫秒防抖，并在退出前提交最终位置。
- 保存稳定屏幕标识（平台可取得时）及相对可用工作区的逻辑坐标；不保存仅进程内有效的显示器编号作为唯一定位依据。
- 恢复时校验数值、目标屏幕和工作区，再限制到可见范围；支持负坐标排列、不同缩放、Dock／任务栏占位及主屏变化。
- 屏幕不存在时回主屏默认位置。重置位置清理已保存位置：开启时立即回默认位置；关闭时只重置，下次开启使用默认位置。
- 监听显示器变化及工作区变化。系统调整工作区但未触发显示器列表变化时，在恢复显示／拖动结束等节点复核边界，必要时补充平台事件。

## 5. 本地偏好与异常策略

继续使用现有 SQLite `preferences` 表，增加独立的 `ui_preferences` 键，不更改提醒配置的 schema，不覆盖 `settings_backup`，无需为一个界面开关新增数据库文件。

建议数据结构：

| 字段 | 说明 |
| --- | --- |
| `schema_version` | UI 偏好自身版本，初始为 1 |
| `floating_enabled` | 默认 false |
| `floating_position` | 可选：屏幕标识及相对工作区逻辑坐标；缺失表示默认位置 |

UI 偏好类型放在存储层独立模块或已有存储模型中，不把像素位置加入纯提醒引擎。存储线程增加独立加载、保存、回执；应用快照区分“已持久化偏好”“保存中”和“错误提示”。

保存策略：

1. 开关操作立即改变窗口显示，并显示保存中状态；通过后台线程保存，失败回到最近已保存的开关状态并给出可见错误。
2. 保存期间合并或禁用重复开关操作；位置与开关更新由同一个 Controller 合并，保存回执带版本或请求标识，防止旧位置保存结果覆盖新开关。
3. 拖动位置写入失败时不把窗口突然拉回旧位置；提示“位置未保存”，保留当前可见位置供本次使用。再次有效拖动或重置可以重试。
4. 缺少 UI 偏好时正常采用默认值；偏好损坏时保留原值、使用默认关闭与默认位置，并显示独立警告。不要把只损坏外观偏好当成核心提醒数据库损坏而停用整套提醒。
5. 退出时把已合并的最后一次 UI 偏好写入加入现有 Flush／Barrier 流程；继续遵守现有退出超时，不让位置保存阻止应用退出。
6. 胶囊创建失败时保留主窗口／托盘入口并报告错误；同一失败不在每秒刷新时无限重试。用户重新开启或明确重试后再创建。
7. 托盘创建失败时主窗口必须可见，不进入只有悬浮窗且无法可靠找回设置的启动路径。

## 10. 平台、打包与外机验证

### 10.1 Windows 10

在现有 Windows 原生模块里实现工具窗口、置顶、非激活显示、工作区和 DPI 适配。圆角与透明绘制不能依赖 Windows 11 的系统效果。特别检查无焦点窗口的鼠标操作与菜单键盘输入，不使用会让整个胶囊无法点击的全窗穿透。

本机缺少 Windows SDK 时，如实记录构建限制；使用可用 Windows 构建环境或现有 CI 执行验证。CI 的 `windows-2022` 是 Windows Server 构建环境，不是 Windows 10 桌面兼容性证明。

### 10.2 Mac 双架构与最终包

实施后沿用现有构建入口：

```bash
scripts/package-macos.sh aarch64-apple-darwin
scripts/package-macos.sh x86_64-apple-darwin
```

Windows 构建环境使用：

```powershell
./scripts/package-windows.ps1 -SkipInstaller
# 已安装 Inno Setup 6 时，生成安装包：
./scripts/package-windows.ps1
```

发布构建标识递增，记录实际包名、架构和 SHA256。继续保留当前新建 staging、ICNS 内容命名、签名检查及 `verify-macos-icon.py` 校验流程，避免再次交付旧图标缓存或旧包。Intel 交叉构建成功不代表 Intel 实机运行通过。

### 10.3 外机步骤文档

已提前准备 [外机专项手册](../validation/FLOATING_WIDGET_MANUAL_TESTS.md)，并在 [现有外机手册](../validation/MANUAL_TEST_GUIDE.md) 加入口。依用户要求，本机交互补验通过后再执行外机验收；手册不代表已通过，覆盖：

1. 下载／辨认确切构建和架构，记录 OS、GPU、屏幕、分辨率、缩放、包哈希，隔离测试数据。
2. 开关、重启、主窗关闭、托盘找回、拖动、图标和倒计时完整性。
3. Windows 10 的 100%／150%／200% 缩放、混合 DPI、多屏负坐标、任务栏占位与屏幕拔除。
4. Intel Mac 的 Retina／外接屏、普通 Space、Dock 占位、明暗切换和窗口失焦行为。
5. 更多菜单在四个屏幕边缘的弹出、键盘操作及关闭；其他应用连续输入时不抢焦点。
6. 强制／轻提醒、5 秒体验、正式休息、锁屏、真实睡眠及恢复后状态核对。
7. 退出后的窗口清理、升级保留偏好与原提醒数据。
8. 每项结果填“通过／失败／未执行”；失败提供复现步骤、时间、实际与期望、相关截图或日志。

外机步骤与设备限制在交付时明确说明；不得将“尚未测试”写成“完全兼容”。
