# 咕嘟扭扭｜macOS 菜单栏与 Windows 托盘常驻实现计划

日期：2026-10-14（Asia/Singapore）
规划状态：complete，已完成源码调查、实现拆分与验收设计。
执行状态：实现及本机可执行检查已交付；原生交互、Windows 完整构建与外机／长稳验收待执行。详见 [本轮报告](../validation/RESIDENT_APP_REPORT.md)。

## 1. 已确认方向

采用菜单栏／系统托盘常驻的交互方式。macOS 正常运行时隐藏 Dock 和 ⌘Tab 入口；Windows 日常后台运行只保留托盘，主动打开主窗口时正常显示任务栏和 Alt+Tab。首次启动展示引导，之后正常冷启动不主动打开主窗口；胶囊沿用用户开关，设置按需打开。

本计划将补齐平台实现、窗口生命周期、异常恢复、任务拆分、回归矩阵与交付门槛。历史文档的 Dock 和 Esc 退出描述不作为本轮新需求。

## 2. 目标、范围与兼容基线

### 2.1 本轮交付目标

1. macOS 使用菜单栏常驻模式：正常启动、打开设置、显示胶囊、提醒条和休息遮罩时，都不出现运行态 Dock 图标或 ⌘Tab 项。
2. Windows 使用托盘常驻模式：没有主窗口时不占任务栏和 Alt+Tab；主动打开主窗口时保留普通窗口的任务栏、最小化和键盘体验。
3. 正常冷启动尽量安静，关闭主窗口一次即隐藏；主窗口、悬浮窗和后台进程的生命周期分别管理。
4. 托盘或窗口创建失败时仍有可操作入口，禁止留下无入口的隐藏进程；再次启动应用能够找回已有实例。
5. 保持现有五项提醒、计时、记录、休息退出规则、用户设置和胶囊位置。纯托盘状态下也能按时提醒。

### 2.2 平台范围

| 平台 | 构建目标 | 必须覆盖的运行环境 |
| --- | --- | --- |
| Apple Silicon Mac | `aarch64-apple-darwin` | macOS 15+，本机正式 `.app` 与开发启动 |
| Intel Mac | `x86_64-apple-darwin` | macOS 15+，Intel 真机正式 `.app` |
| Windows | `x86_64-pc-windows-msvc` | Windows 10 x64、Windows 11 x64，便携版与安装版 |

沿用 Rust 1.97.1、GPUI Kit 0.7.3、gpui-pre 0.3.9、Cargo.lock 中 tray-icon 0.24.2。Windows ARM64 原生构建、macOS 14 及更早版本不在本轮新增承诺内。Windows Server CI 构建成功不能替代 Windows 10／11 桌面实测。

### 2.3 范围控制

本轮采用统一的常驻默认行为，不增加“隐藏 Dock”开关，不引入系统服务、LaunchAgent、Windows Service、开机自启或第二个守护进程。菜单栏与托盘图标保留；胶囊是否显示继续由现有设置控制。图标资源继续用于 Finder、开始菜单、安装器、通知和故障兜底。

资源优化以测量为依据。正常冷启动不创建主窗口可以减少窗口初始化；用户打开后再隐藏时保留窗口实体与草稿，不为了省内存而销毁编辑状态。隐藏 Dock 本身不作为 CPU 或内存改善证据。

## 3. 用户可见行为

### 3.1 启动与打开

| 场景 | 统一行为 | macOS | Windows |
| --- | --- | --- | --- |
| 首次启动、尚未完成引导 | 展示引导；确认并保存成功前不开始正式提醒 | 无 Dock，菜单栏图标可用 | 主窗口出现在任务栏和 Alt+Tab |
| 完成引导 | 保存成功且托盘可用后进入常驻；胶囊按开关显示；保存失败或托盘不可用保留窗口及错误 | 只留菜单栏和可选胶囊 | 主窗口隐藏，托盘和可选胶囊保留 |
| 已引导、正常冷启动 | 建立托盘，恢复设置；不创建或展示主窗口 | 无 Dock／⌘Tab | 无主窗口任务栏／Alt+Tab 项 |
| 暂停、下班、所有提醒关闭 | 同样安静启动；托盘状态反映真实状态 | 不因没有倒计时而打开窗口 | 同左 |
| 正在运行时再次启动应用 | 激活已有主窗口，不启动第二套引擎 | Finder／Spotlight／重复执行均可找回 | 开始菜单／快捷方式／重复 EXE 可找回 |
| 点击“打开小站” | 创建或恢复唯一主窗口，保留当前页面与草稿 | 显示并可编辑窗口，仍无 Dock | 恢复隐藏或最小化窗口，显示任务栏项 |
| 点击“提醒设置” | 通过现有导航保护进入设置页 | 不切换为 Regular | 正常前台窗口 |
| 数据损坏、UI 偏好读取失败 | 打开处理窗口并展示具体原因 | 托盘正常时仍是 Accessory | 普通主窗口 |
| 托盘不可用 | 打开兜底主窗口，显示重试及退出入口 | 临时改为 Regular，恢复 Dock／⌘Tab | 保留普通任务栏窗口 |

冷启动与重复启动必须分开：用户第一次启动已配置的程序进入常驻；随后再次启动用于找回窗口。引导和设置页明确提示“应用在菜单栏／系统托盘运行，可从图标打开小站”。Windows 补充“图标可能位于 ∧ 展开区”。系统允许用户把图标收起或手工固定快捷方式，本程序不更改这些偏好。

### 3.2 关闭、最小化与退出

| 操作 | 目标行为 |
| --- | --- |
| 主窗口关闭按钮／Mac ⌘W／Windows Alt+F4 | 托盘可用时一次隐藏主窗口，后台继续；去除当前“第一次提示、第二次才隐藏”逻辑 |
| 隐藏带未保存设置的主窗口 | 保留同一窗口实体与草稿；重新打开仍在原页面，不自动保存或丢弃 |
| 主窗口最小化 | 保留操作系统原生最小化语义；Windows 仍有任务栏项，从托盘打开会还原 |
| 首次引导中关闭 | 托盘可用时允许隐藏，但不启用提醒；再次打开回到未完成引导 |
| 托盘不可用时关闭主窗口 | 保留最后一个可操作窗口，展示“重试托盘”／“退出应用”；不能静默隐藏最后入口 |
| 胶囊系统关闭／菜单内隐藏 | 关闭并保存胶囊开关，后台提醒继续；不退出应用、不自动打开主窗口 |
| 胶囊菜单 Esc／外部点击 | 只收起菜单 |
| 全屏休息 Esc、返回键、⌘W／Alt+F4、窗口关闭请求 | 不结束本次休息；延续 `758483f` 的退出约束 |
| 遮罩灰色带下划线文字按钮 | 立即结束本次休息并撤下全部遮罩；正式休息只记一次中断，体验不记账 |
| 托盘“退出咕嘟扭扭”／关于页退出／现有应用退出快捷键 | 保存已提交数据、清理窗口与托盘，结束进程；隐藏不等于退出 |

设置草稿仍只在明确保存后持久化，退出不自动提交草稿。本轮不新增退出草稿自动保存机制。系统关机、强制结束进程保留系统行为，不尝试拦截；原有崩溃恢复继续负责未完成会话。

### 3.3 托盘菜单

沿用原生菜单，提供：打开小站、提醒设置、当前状态（不可点击）、显示／隐藏悬浮窗、暂停 15 分钟／1 小时／下一工作日／手动暂停、恢复提醒、退出应用。复用既有命令，不新增一套设置和提醒状态。

macOS 点击菜单栏图标打开菜单。Windows 右键打开菜单，左键单击打开小站；明确关闭库默认的左键弹菜单行为，避免一次点击既开窗口又弹菜单。重复点击仅恢复同一个窗口。键盘通过系统通知区域及原生菜单能够进入设置、暂停和退出。

“暂停”和“退出应用”沿用已有全局语义，会影响当前提醒；本轮不把应用变成锁机工具。日常手动中断休息仍通过遮罩文字按钮，不恢复已移除的托盘紧急退出菜单。

## 5. 生命周期与代码组织

### 5.1 最小结构调整

继续由现有 Controller 持有引擎、托盘、主窗口和辅助窗口。可增加小型 `resident.rs`，仅封装可测试的启动／显示决策及托盘可用性状态，不建立第二个全局控制器，也不改 `gulu-core` 计时职责。

区分以下事实，不用一个布尔值混合表示：

- 托盘对象是否存在、平台是否确认已注册、最近一次检查是否失败。
- 主窗口是否创建、实际是否显示；最小化由平台窗口状态处理。
- 当前是否引导／恢复／休息／锁屏／退出；这些值从现有状态读取。
- 是否有因锁屏或休息暂缓的显式打开请求；记录目标页，结束后最多处理一次。

启动与关窗决策写成少量纯函数并测试；平台操作由现有 `platform` 层完成。状态变化及失败原因写入已有 `GULU_DIAGNOSTICS`，不记录用户输入。

### 5.2 冷启动顺序

1. 沿用数据目录和单实例锁。第二个进程只发激活信号并退出，不创建托盘、窗口或计时器。
2. 读取配置、UI 偏好、暂停状态与崩溃恢复结果。
3. 创建正常的 GPUI 图形应用；macOS 在运行循环启动前配置 Accessory；设置显式退出。
4. 初始化主题、平台事件、应用身份；建立托盘并取得注册状态。
5. 发布首个快照并同步胶囊／提醒条；仅在需要引导、用户处理错误、托盘兜底或已收到显式打开请求时创建主窗口。
6. 进入现有事件循环。无窗口不是退出条件，也不是停止计时条件。

### 5.3 打开与焦点

`Open` 表示恢复原页面；`OpenHome`／`OpenSettings` 带导航目标。已有主窗口尽量复用；平台恢复后再激活，避免最小化窗口收到激活却仍不可见。创建失败不能留下假的 `main_visible = true`。

显式打开来源包括托盘、重复启动、胶囊点击和通知点击。普通计时、托盘状态更新、胶囊恢复、显示器变化不主动激活主窗口。正常设置窗口在 macOS Accessory 下可获得键盘焦点，不通过临时切 Regular 来显示。

锁屏期间不弹处理窗口；强制休息／体验期间不让设置窗口盖住退出文字。显式打开请求暂存，解锁且休息结束后执行；若同时发生退出，丢弃待执行打开请求。后台提醒条继续使用非激活显示；正式休息保留其现有激活与结束焦点恢复逻辑。

托盘菜单或辅助窗口得到焦点时，主窗口关闭路由不能误作用于遮罩。全局关闭快捷键继续按窗口来源分流，重复原生关闭通知不得改变提醒结果。

### 5.4 退出

进入退出状态后拒绝新建主窗口、托盘重建和待执行打开请求；按现有顺序隐藏／销毁辅助窗口、撤下遮罩、结算引擎、提交已确认设置与窗口位置。收敛显式退出与 `on_app_quit` 的清理，避免重复结算；保留有限等待和异常恢复，不无限等待存储。

最后释放托盘、文件监视器和单实例锁。验收包括从“仅托盘、无主窗口”的状态退出、退出过程中再次启动、存储写入失败时退出。

## 6. macOS 方案

### 6.1 包与运行时同时设置

- 在 Info.plist 添加 `<key>LSUIElement</key><true/>`，让 LaunchServices 从一开始按 Agent App 启动；不设置 LSBackgroundOnly，因为仍需要窗口。
- 在正常 `application()` 构造链中，仅 macOS 使用 `with_windowing(WindowingRequest::Headless)`。锁定版本源码表明它将初始激活策略设为 Accessory，并在 AppKit 运行循环启动前应用，避免 Dock 启动闪现。
- 此处 Headless 是该 API 在 macOS 上的策略名称，不改用没有图形能力的 headless platform。后者没有同样的窗口能力，不可替换。
- 正常打开窗口路径不调用 `request_windowing(Windowed)`；该调用会切回 Regular。必要时统一封装 `set_activation_policy`，仅托盘失败兜底允许切 Regular。
- 开发启动没有 `.app` 元数据，靠运行时策略获得相同表现；正式包必须同时验证 plist 与实际行为。

已有 `open_window` 及 GPUI Kit Root 包装不会自行请求 Regular，源码具备实施基础；这不等于实际窗口焦点、菜单和系统通知已通过。

### 6.2 无 Dock 后的操作入口

常驻入口由菜单栏状态图标承担，不依赖应用菜单、Dock 右键或 ⌘Tab。主窗口打开后仍能输入、切换控件及使用窗口内快捷键；主窗口未激活时，不注册会截获其他应用 ⌘Q／⌘W 的全局快捷键。

Finder 图标与应用包身份保留。再次从 Finder／Spotlight 启动应触发现有 `on_reopen` 或单实例激活信号，实际验证 OS 回调顺序，避免正常冷启动误触发主窗口。用户自己固定在 Dock 的快捷方式不由应用删除；验收针对运行态 Dock 展示。

### 6.3 菜单栏失败兜底

创建托盘失败时，先切 Regular，再显示并激活主窗口，提供“重试菜单栏图标”和“退出应用”。重试成功后可切回 Accessory，但当前处理窗口保持可见，直到用户主动关闭；后台恢复不自动夺走正在使用的窗口。

若托盘和主窗口都创建失败，使用现有原生错误对话框提示，并沿正常清理路径结束进程。窗口被普通 Space、全屏应用或其他窗口遮挡不等于创建失败，不能因此反复重建。

## 7. Windows 方案

### 7.1 按窗口角色管理任务栏

| 窗口角色 | 任务栏／Alt+Tab | 激活行为 |
| --- | --- | --- |
| 主窗口／设置／引导／兜底窗口 | 显示时有正常任务栏与 Alt+Tab 项 | 用户显式打开时还原并激活 |
| 主窗口隐藏 | 无运行态窗口项；用户固定快捷方式仍可能保留 | 不抢焦点 |
| 胶囊、提醒条 | 清除 WS_EX_APPWINDOW，设置 WS_EX_TOOLWINDOW | 被动显示不激活 |
| 胶囊菜单 | 无任务栏／Alt+Tab 项 | 用户打开时允许键盘导航 |
| 全屏休息遮罩 | 各屏都无独立任务栏／Alt+Tab 项 | 保留现有休息焦点能力 |
| 托盘内部事件窗口 | 永远不显示 | 库内部维护 |

提取小型辅助窗口样式函数，仅处理必要的扩展样式；主窗口不应用 TOOLWINDOW。全屏遮罩不能直接复用包含圆角、尺寸和浮动位置逻辑的 `prepare_floating`。辅助窗口在首次显示前设置样式，避免任务栏短暂闪现；使用框架隐藏创建与适当的 FRAMECHANGED 生效流程。

不为遮罩或菜单一律设置 WS_EX_NOACTIVATE，因为这些窗口仍可能需要焦点。主窗口打开时通过平台 helper 处理 `ShowWindow`／还原最小化，再使用 GPUI／系统的激活路径；遵守 Windows 前台限制，不添加抢前台的循环。

### 7.2 托盘可用性与 Explorer 重启

tray-icon 0.24.2 已监听 TaskbarCreated，Explorer 重启后应由库重新注册图标。本轮复用这条路径，避免自建第二套 NIM_ADD 导致重复图标。

但库在第一次 `Shell_NotifyIconW(NIM_ADD)` 失败时可能仍返回有效 Tray 对象，因此：

1. 在 Windows 托盘创建后，用库已有、会返回 Shell 修改结果的 `set_tooltip` 做一次注册可用性确认，使用相同的固定提示文案；失败时保留库对象等待恢复，同时打开兜底主窗口。
2. 在已有后台事件循环中安排最长 30 秒一次的低频注册确认，并在关闭最后主窗口前确认；不要随每秒倒计时重复检查，不额外创建线程或忙轮询。
3. 原生通知区域图标被收进 ∧ 不是失败；不以图标坐标缺失、图标是否展开或用户肉眼可见作为注册成功标准。
4. 库在 TaskbarCreated 后恢复成功时，下一次确认清除错误；恢复不会新建主窗口或重复注册菜单回调。
5. 发生一次故障只提示一次；锁屏／休息期间暂缓兜底窗口展示，结束后处理。持续失败时保留主窗口；“重试托盘”优先检查现有对象，必要时先释放旧对象再重建。

实施阶段先做 Win32 小范围实验确认该探测在 Windows 10／11 的行为和返回值；若锁定版本不能提供可靠结果，再对最小适配接口作调整，不直接升级整套 GUI 依赖。

## 8. 数据、异常与资源开销

### 8.1 数据兼容

本轮不新增持久化开关、不变更 Settings 或 UiPreferences schema，不重写用户设置。所有已完成引导的用户升级后采用安静冷启动；默认间隔仍为喝水 30、颈肩 40、如厕 90、站立 60、护眼 20 分钟，已保存间隔保留。

配置读写、日期切换、提醒结算、单实例路径和应用标识继续使用原实现。主窗口隐藏保留页面和内存草稿；点击通知走导航保护，不能借 `saved()` 清空未完成的页面切换状态。

### 8.2 失败处理

| 故障 | 行为与可恢复入口 |
| --- | --- |
| 托盘创建或注册失败 | 普通主窗口兜底；Mac 临时 Regular；禁止隐藏最后入口 |
| 托盘可用但主窗口创建失败 | 原生错误提示／可操作菜单保留，允许下次显式打开重试；不停止计时 |
| 托盘与主窗口均失败 | 原生错误提示后清理退出，不留不可见进程 |
| 悬浮窗开启但创建失败 | 托盘继续可用；显示一次故障说明并提供设置入口，不因每次刷新反复弹窗 |
| 数据损坏或恢复失败 | 打开原有恢复界面，保留原文件；正式提醒按原规则暂不启动 |
| 后台记录持久化失败 | 保留重试和错误状态；托盘状态可识别“需要处理”，窗口不反复抢焦点 |
| Windows Explorer 重启 | 托盘库恢复注册；确认失败时提供主窗口兜底；不改变计时或重复生成记录 |
| 睡眠、锁屏、拔屏 | 继续原有计时和显示器处理；无主窗口时也接收事件；休息结束撤下全部遮罩 |

### 8.3 性能测量

不修改提醒引擎的有效时间规则，不为隐藏图标而强行降低调度精度。复用 `wait_ms` 和可见性判断，后台不刷新隐藏主窗口；托盘状态或菜单文本实际变化时才更新。

在同一台机器、同一份隔离配置、同一 Release 构建方式下，对比 `758483f` 和新版本：纯托盘、托盘加胶囊、主窗口打开三种状态分别记录 CPU、内存及可见窗口数量。空闲性能按原 PRD：预热 5 分钟后采样 30 分钟，平均 CPU ≤ 单个逻辑核的 0.5%，Windows 工作集／macOS RSS P95 目标 ≤ 200 MiB；注明指标差异。没有证据前不宣称资源占用已显著降低；超预算须记录原因并评估，不能仅凭图标隐藏判通过。

## 10. 验证与验收矩阵

### 10.1 自动化

- 对启动决策做表驱动测试：首次／已引导 × 托盘正常／失败 × 胶囊开／关 × 数据正常／恢复，确保“关胶囊”不会打开主窗口。
