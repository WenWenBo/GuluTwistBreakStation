# 护眼与分项提醒方式｜需求分析与澄清

日期：2026-10-13。状态：核心需求及三个关键边界已由用户确认；用户已授权按本方案实施，正式基线已同步到 PRD v1.1。

本次需求来自用户的实际使用反馈：喝水、颈肩、如厕和站立都遮罩屏幕，打断过重；希望这些事项轻量提示、一键完成，护眼默认使用全屏休息。本文记录新需求、用户确认结果及交互建议；实现与验证结果见 [交付报告](../validation/EYE_CARE_REMINDERS_REPORT.md)。原需求基线见 [PRD](PRD.md)，胶囊尺寸依据见 [胶囊方案](../design/FLOATING_WIDGET_PROPOSAL.md)。

## 1. 已明确的需求

| 事项 | 用户明确要求 |
| --- | --- |
| 新增保护眼睛 | 默认间隔 20 分钟，每次休息 20 秒 |
| 默认提醒方式 | 保护眼睛默认全屏；喝水、颈肩、如厕、站立默认轻提醒 |
| 分项配置 | 各事项保留全屏／轻提醒选择，保护眼睛也能改成轻提醒 |
| 轻提醒展示 | 到期后在胶囊下方出现提醒条，带圆形勾选按钮 |
| 完成 | 点击勾选即完成，移除该条，开始本项下一轮计时 |
| 未完成 | 在当前工作时段持续保留；工作时段结束或应用退出时清空，重启不恢复旧待办 |
| 胶囊关闭 | 到期临时显示独立提醒条，完成后隐藏；不重新开启常驻胶囊 |
| 旧版本升级 | 原四项改成轻提醒，保留间隔、启用开关和历史记录；新增护眼默认开启并使用 20 分钟／20 秒全屏 |
| 全屏护眼 | 选择全屏方式时，到期仍覆盖全部屏幕并倒计时 |

“全屏休息”仍是可紧急退出的应用遮罩，沿用现有退出入口。按工作时段累计间隔、锁屏／睡眠暂停间隔、已开始的休息计入睡眠经过时间，继续沿用已有约定。

## 2. 建议的设置与默认值

提醒方式从一个全局选择改为每项独立选择。设置中每一项提供启用开关、间隔和提醒方式；全屏方式再显示休息时长。切成轻提醒后保留原休息时长，以便切回全屏。

| 事项 | 新用户默认间隔 | 默认方式 | 全屏时的默认时长 |
| --- | --- | --- | --- |
| 咕嘟喝水 | 60 分钟 | 轻提醒 | 30 秒 |
| 扭扭颈肩 | 45 分钟 | 轻提醒 | 60 秒 |
| 如厕放风 | 120 分钟 | 轻提醒 | 180 秒 |
| 站立活动 | 60 分钟 | 轻提醒 | 120 秒 |
| 保护眼睛 | 20 分钟 | 全屏休息 | 20 秒 |

现有四项的默认间隔与时长沿用原产品设置，用户已有自定义值保留。用户已确认新增护眼默认开启。上述升级只在迁移旧配置时执行一次，不在后续启动时覆盖用户逐项修改的方式。默认值不代表医疗效果承诺。

轻提醒没有强制停留时间：护眼改为轻提醒后，也按用户要求使用提醒条和勾选完成，不要求等满 20 秒才能勾选。提示语可为“让眼睛休息一下，看看远处”。

首页的单一“强制休息／轻提醒”标签需同步调整，避免在混合配置下误导；建议显示“护眼全屏 · 其余轻提醒”或“按事项提醒”。保留全局暂停入口，不新增另一个会覆盖单项选择的全局模式。

## 3. 建议的胶囊交互

主胶囊保持 200 × 52、两端半圆及现有应用图标。提醒条独立附着在其下方，不把主胶囊撑高。

**胶囊关闭时的已确认行为：** 不显示常驻倒计时，到期仍显示独立提醒条，完成后收起。多项待办时，仅移除完成项，最后一条处理完才隐藏整组。建议使用胶囊保存的位置作为锚点，未设置位置时放在主屏工作区右下方，并进行屏幕边缘校正。该行为不修改胶囊开关；设置旁提示“关闭悬浮窗后，到期仍会显示提醒条；暂停提醒请使用暂停功能”。

以下尺寸、排序与布局属于交互建议：

- 每条约 200 × 40 逻辑像素，圆润浅底，短文案例如“喝口水吧”，右侧是圆形勾选按钮。圆形按钮 28 像素。
- 多种事项到期时纵向排列，按到期先后稳定排序。同一事项最多一条，不周期性叠加重复提醒。
- 未完成事项停留在待处理状态，尚未开始下一轮间隔；其余事项继续按各自规则计时。
- 主胶囊继续显示下一个尚未到期事项的倒计时；待完成内容由下方提醒条承载。所有启用事项都在待处理时显示“全部待处理”，不显示虚假的倒计时。
- 勾选后只结算该事项一次、移除该条，并从完成时刻重新累计本项完整有效时间；其它事项与待办不被重置。重复点击不重复记账。
- 拖动胶囊时提醒条跟随；按钮点击不触发拖动或打开主窗口。
- 提醒出现和更新不抢输入焦点、不自动打开主窗口、不循环响铃。轻提醒建议以提醒条为主，胶囊开启或关闭都不额外重复弹系统横幅；提醒条创建失败时才降级系统通知＋主窗口待办。
- 胶囊靠屏幕底部、下方空间不足时，建议整组提醒条翻到上方；整组位置限制在工作区；当前支持可容纳五条提醒的桌面工作区。
- 主窗口继续提供完整的完成、稍后、跳过操作，提醒条只保留最常用的勾选。稍后会暂时收起对应条目，到期再显示；跳过不计为完成。

**保留范围已确认：** 未完成条目只在当前连续工作时段内保留，不按现有超时规则自动过期，不重复生成同项提醒。工作时段结束（含进入午休）或应用退出时清空，记为取消而非完成；下个工作时段／重启从完整间隔开始，不补发旧待办。

全屏休息、锁屏／睡眠时临时隐藏；只要恢复时仍在原工作时段，待办仍恢复显示。若期间已跨过该工作时段结束边界，则清空，不在解锁后补弹。全局暂停期间建议暂时隐藏提醒条并显示胶囊“已暂停”，在原工作时段恢复后待办仍在。关闭某项提醒则明确取消该项待办，不记完成。

## 4. 混合提醒时的规则建议

| 场景 | 建议行为 |
| --- | --- |
| 喝水未完成，护眼到期 | 护眼正常开始全屏 20 秒；胶囊与轻提醒条临时隐藏；结束后喝水条恢复 |
| 喝水与护眼同时到期 | 喝水进入轻提醒待办，只有护眼进入全屏会话；不把喝水合并为强制事项 |
| 护眼休息完成 | 只完成护眼，不替用户完成喝水等其它待办 |
| 用户将站立也设为全屏，且与护眼同批到期 | 沿用现有强制提醒合并规则：只合并全屏事项，时长取其中最长值，分别记账 |
| 护眼设为轻提醒 | 到期显示与其他事项相同的提醒条，勾选完成；不自动遮罩 |
| 全屏休息期间 | 其它提醒间隔沿用现有规则暂停；已存在的轻提醒待办保留 |
| 紧急退出全屏 | 沿用中断记录与恢复缓冲；不记作计时完成，不影响已有轻提醒待办 |
| 到工作时段结束或退出应用 | 清空未完成轻提醒，不记完成；下次从完整间隔开始，旧条目和延迟点击不得重新结算 |
| 修改某项提醒方式 | 建议当前已到期轻提醒保持可处理，新方式从下一个实例生效，避免保存设置立即弹遮罩 |

## 5. 当前实现的影响范围

已核对当前源码和 PRD：

1. 现有四种事项和配置数量需要扩展为五种，设置、首页、首次引导、记录、图标、文案与摘要都要包含护眼。
2. 当前只有全局强制／轻提醒模式，需要改为分项模式，并核对混合到期与合并行为。
3. 当前胶囊优先显示“待处理”而不再显示后续倒计时，需要区分“未来最近事项”和“待处理列表”。
4. 当前轻提醒存在超时失效，并会在锁屏、休眠、全局暂停、工作时段结束时取消。按已确认范围，需取消当前时段内的自动过期、锁屏／休眠清除；工作时段结束与退出清除继续保留。全局暂停建议改为临时隐藏，不提前取消当前时段待办，不能只修改界面。
5. 用户选择退出清空、重启不恢复旧待办，因此继续沿用当前冷启动从完整间隔开始的方向；仍须确保退出与完成同时发生时只记账一次、异常重启不重现旧提醒。
6. 老配置只有四项和一个全局模式，升级必须兼容旧数据、保留现有间隔／开关和历史记录，明确新模式的迁移策略。
7. 提醒条需要与胶囊共同处理拖动、显示器边缘、隐藏、菜单、全屏遮罩与点击焦点，并继续覆盖 Windows 10、Apple Silicon Mac 和 Intel Mac。

整体可行，属于提醒规则和桌面交互的一次功能扩展。可复用现有工作时段、完成记账、全屏遮罩、胶囊与设置能力；兼容结论仍需平台实测。

## 6. 用户确认记录

| 编号 | 问题 | 用户选择与最终边界 |
| --- | --- | --- |
| D-01 | 关闭胶囊后的轻提醒 | “到期时临时显示独立提醒条，完成后隐藏”；不擅自打开常驻胶囊 |
| D-02 | 未完成待办保留期限 | “仅在当前工作时段保留，下班或退出时清空”；不跨工作时段、不跨重启积累 |
| D-03 | 已有配置升级 | “现有四项改成轻提醒，按本次新规则启用”；保留原开关／间隔与记录，新增护眼默认开启、20 分钟／20 秒全屏 |

核心边界已清楚，无需追加阻挡性问题。提醒条尺寸、位置回退、全局暂停期间呈现及已到期事项修改方式的生效时机按本文建议进入下一步设计／计划；用户随后确认实施，规则已同步为 PRD v1.1；本文保留澄清过程，实际交付状态以报告为准。

## 7. 验收场景草案

- 新增护眼后，五项均可独立开关、改间隔与方式；重启保留；升级不损坏旧记录和用户自定义间隔。
- 喝水轻提醒到期产生一条待办，长期不处理不重复叠加；完成仅记一次，下一轮从完整间隔开始。
- 两项轻提醒到期显示两条；完成其中一条不影响另一条和主胶囊的最近倒计时。
- 护眼全屏到期正确覆盖全部屏幕 20 秒；自然结束与紧急退出均撤罩；结束后原轻提醒条恢复且未被自动完成。
- 护眼切轻提醒后不遮罩；其他事项切全屏后按各自配置遮罩；强弱同时到期不串用方式。
- 验证无未来事项、全部关闭、暂停、下班、锁屏、睡眠和重启；核对当前时段保留、跨时段／退出清空，以及关闭胶囊仍出现独立提醒条。
- 完成勾选、拖动、菜单、主窗口操作互不误触；混合缩放、底边翻转、跨屏和关闭后找回可用。
- 验证完成持久化失败、快速重复勾选、旧回调及迁移失败，不出现虚假完成、重复记账或待办无声丢失。
