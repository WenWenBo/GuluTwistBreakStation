# 桌面悬浮窗 · 可行性与设计建议

日期：2026-10-13。状态：用户已确认 200 × 52 的紧凑胶囊及两端完整半圆外观，并已授权实施；功能代码已在 `feat/compact-floating-capsule` 实现，自动检查和 Mac 双架构打包通过，本机桌面与外机运行尚待验证，见[验证报告](../validation/FLOATING_WIDGET_REPORT.md)。开发步骤与精确状态规则见 [实现计划](../implementation/FLOATING_WIDGET_PLAN.md)，不代表通过平台实测。

## 结论

可以在现有 Rust + GPUI Kit 架构上实现，无需更换框架。建议增加一个常驻的圆角胶囊式小窗，作为日常查看入口；主窗口继续负责完整设置、今日记录和提醒处理。用户可以关闭主窗口，只保留托盘与悬浮窗。

实现复杂度中等。主要工作是窗口管理、真实计时状态映射及跨平台细节；无需另建一套提醒系统。Windows 10 与 Intel Mac 的最终运行效果仍需实机确认。

## 外观建议

| 形态 | 优点 | 取舍 |
| --- | --- | --- |
| 圆角胶囊，推荐首版 | 同时看清应用图标、事件名称、倒计时；横向占用较小 | 比纯图标多占一些宽度 |
| 圆球 | 形象可爱，适合只放角色与简短时间 | 加入事件名称和较长时间后需要增大直径；更多操作不易发现 |

根据用户反馈，修订内容面板为 **200 × 52 逻辑像素**，比原方案 260 × 88 高度减少约 41%、面积减少约 55%。两端为完整半圆，半径取高度的 50%，即 26；上下边保持平直，形成真正的胶囊。HTML 预览用足够大的等值圆角实现此效果，不能直接用宽高各自的 50% 生成椭圆。外层为阴影另留透明边距。奶白背景、深绿色文字、细边线与轻阴影，沿用当前“小咕”品牌；预览随亮暗主题切换。

- 左侧使用现有圆润应用图标，布局盒约 38 × 38，可见图案约 31 × 31。保留图标自身透明四角，不再套一个有棱角的底框。
- 中间上方直接显示“咕嘟喝水”等事项名称，字号 12、行高 15；下方显示等宽倒计时，例如 `18:32`，字号 20、行高 23。去掉重复的“接下来”前缀，减少视觉负担。
- 右端居中保留一个小“更多”入口，鼠标点击区 28 × 28，提供暂停／恢复、打开设置、隐藏悬浮窗。触摸预览扩大有效点击区至 44 × 44。
- 时间采用固定宽度和明确行高；预留 `240:00` 的完整宽度，避免数字和冒号裁切。事件标签过长时收敛为“喝水 + 1 项”，完整内容可查看。
- 不闪烁冒号、不做持续跳动动画、不每秒改变窗口大小。最后一分钟可以调整文字提示，但不能只靠颜色表达到期。

用户已选择胶囊，当前修订预览只展示该形态。圆球保留为前期探索，不列入首版范围。

## 日常交互与开关

1. 默认放在主屏可用工作区右下角，距离边缘约 24 逻辑像素，避开 Dock／任务栏。支持拖动，松手后记住屏幕与位置；拖动空白区域，点击图标或时间打开主窗口。明确区分点击与拖动，避免拖完意外打开主界面。
2. 窗口显示及每秒更新不抢键盘焦点；点击打开主界面才激活应用。置于普通应用窗口上方，层级低于强制休息遮罩；不新增一个独立任务栏入口。
3. 设置中增加“桌面悬浮窗”分组，提供“显示桌面悬浮窗”和“重置位置”。开关即时生效、独立保存；失败时显示错误并恢复一致状态，不影响提醒规则表单中的未保存编辑。
4. “隐藏悬浮窗”等同关闭设置开关，重启后保持关闭。只隐藏这个小窗，不暂停提醒、不清空记录、不重置倒计时。托盘中提供显示／隐藏入口，保证主窗口关闭后仍能找回。
5. 升级现有用户默认关闭，首次启用由用户选择；新用户可以在引导中选择开启。开启后正常启动以托盘和悬浮窗为日常入口；主窗口仍可随时打开。存储错误、首次引导等需要处理的状态应保留清晰的主界面入口。
6. 一次只显示一个悬浮窗。屏幕拔除、分辨率或缩放变化后校正位置，不能留在不可见区域；通过“重置位置”提供无需拖动的恢复方式。

## 倒计时与状态规则

“最近事件”是启用事项中最早到期的一项，包含正常等待与“稍后提醒”。倒计时表示剩余有效工作时间，不承诺固定的墙上时钟时刻；锁屏、暂停和非工作时段遵循当前引擎规则。

| 状态 | 悬浮窗行为 |
| --- | --- |
| 正常工作中 | 显示最近事项及剩余有效时间，每秒更新 |
| 多项同时到期 | 固定顺序显示“喝水 + 站立”或“喝水 + 1 项”，不来回轮播 |
| 轻提醒已经到期 | 优先显示“喝水时间到”／“2 项待处理”，点击进入现有处理界面；不继续显示未来事项掩盖待办 |
| 引擎合并、冷却或解锁缓冲 | 已到期未通知显示“待提醒”；解锁缓冲已直接调整引擎剩余时间，显示核算后的真实时间，不额外猜测“恢复准备中”阶段 |
| 提醒已暂停 | 显示“已暂停”与恢复入口，时间不继续递减 |
| 非工作时段 | 显示“下班啦”及下次工作开始时间，不伪装成正在倒计时 |
| 所有事项关闭 | 显示“提醒未开启”，点击进入设置 |
| 正式休息／遮罩体验 | 临时隐藏悬浮窗，避免遮挡退出按钮；结束后按开关状态恢复 |
| 锁屏／睡眠 | 不尝试覆盖锁屏；唤醒后读取真实引擎状态，遵循已有间隔暂停、休息继续规则 |
| 数据异常／首次引导未完成 | 显示明确状态及处理入口，或先展示主界面；不生成无效时间 |

到期排序使用结构化毫秒值，显示时统一向上取整；不解析主界面的中文时间字符串。相同到期时间以事项固定顺序稳定呈现。全局暂停、休息、错误等状态优先于普通最近事项。

## 技术可行性与改动范围

已阅读当前工程与本机依赖源码，以下是代码能力评估，不等同于已做窗口运行验证。

| 现有基础 | 可复用能力与需要补充的部分 |
| --- | --- |
| `crates/gulu-app/src/main.rs` 中的 Controller | 已管理主窗口和多屏遮罩；增加独立悬浮窗句柄、生命周期与状态通知 |
| `crates/gulu-core/src/engine.rs` | 已提供各事项 Waiting／Snoozed／Pending／Breaking 状态及剩余毫秒；增加统一、可测试的最近事项投影，必要时暴露合并／缓冲状态 |
| 主循环 `wait_ms` | 目前主窗口隐藏后可能最长 30 秒刷新；悬浮窗显示有效倒计时时需要纳入 1 秒刷新条件。隐藏或无需倒计时后降低刷新频率 |
| GPUI 的 WindowOptions 与窗口拖动 API | 有窗口位置、透明背景、初始不聚焦、Floating／PopUp 类型和原生拖动入口；具体平台行为仍需适配验证 |
| macOS／Windows 原生平台层 | 已有原生窗口句柄与置顶操作，可以增设悬浮窗专用配置；不能照搬会主动激活应用的强制遮罩路径 |
| 本地存储 | 新增独立 UI 偏好，保存开关、屏幕标识和逻辑坐标，旧配置缺失时默认处理；不改变原有提醒数据 |

当前 `replace_settings` 只在模式、工作时段等规则或某事项间隔／启用状态改变时重置对应计时，并非所有保存都会重置。悬浮偏好仍建议独立保存，避免与规则保存及主表单草稿耦合。

窗口应订阅同一个引擎快照，不能自行每秒减一充当第二套计时器。位置持久化在拖动结束或短暂防抖后执行，不在每次移动或倒计时刷新时写盘。图标直接使用应用内嵌资源，正式安装包不依赖项目目录。

## 平台细节

- **macOS**：需要验证无标题栏、透明四角、窗口失焦后仍可见、首次显示不抢焦点、拖动和多 Space。GPUI `Floating` 的定义是浮在父窗口之上，不能仅凭类型名称认定已满足跨应用置顶。全屏应用上是否显示需单独确定并验证；首版以普通桌面可见为验收范围。
- **Windows 10**：通过原生窗口样式处理置顶、工具窗口和非激活显示；圆角应由内容／透明窗口实现，不能依赖 Windows 11 的系统圆角。验证 100%／150%／200% 缩放和跨屏移动。
- **Intel Mac**：沿用现有构建目标，但新窗口行为仍需在 Intel 实机运行确认。
- **共同约束**：系统安全桌面／锁屏与独占全屏不承诺覆盖；只在本机完成验证不能代表所有平台已通过。

## 建议实施顺序与验收

1. 增加结构化最近事项状态与 UI 偏好；验证排序、同时到期、稍后、暂停、工作时段和配置兼容。
2. 本机实现胶囊窗口、拖动、开关、托盘入口与状态同步。验证关闭主窗口仍每秒更新，开关不改变原倒计时。
3. 检查真实应用切换、焦点、锁屏唤醒、正式遮罩与体验遮罩，以及拔屏后位置恢复。倒计时的 `00:01`、`00:00`、`120:00`、`240:00` 均完整可见。
4. 完成 Windows 原生适配、Intel 打包，并更新跨机器手工验证步骤；用户按实际设备执行验证。

可访问性要求：图标与更多菜单有操作名称，暂停和错误同时用文字表达，数字不逐秒触发读屏播报；菜单可键盘操作，位置可通过设置重置。验收需比较真实主窗口和悬浮窗状态、检查安装包内图标，并确认高频刷新没有引入忙循环。
